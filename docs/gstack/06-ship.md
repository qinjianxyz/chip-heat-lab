# 06 Ship

## GStack Role

This file is the ship contract for the GStack lane. It is meant to keep the
hackathon repo from drifting into either a pretty-only demo or an overbroad chip
simulation claim. The current scope lock is:

```text
one stylized AI accelerator floorplan
  + steady thermal benchmark
  + transient thermal-dose benchmark
  + bounded power-delivery proxy
  + composed design-review recommendation
```

Shipping means those four Rust-owned proof surfaces are green, the site/native
demo present the same value loop, the GBrain KB explains the assumptions, and
the founder has approved the submission copy/video.

## Ship Gate

Ship only after:

- Rust tests pass.
- CLI emits a valid result for the flagship scenario.
- `scripts/run_value_benchmark.sh` passes and writes
  `benchmarks/value_loop/results.json`.
- `scripts/run_transient_value_benchmark.sh` passes and writes
  `benchmarks/transient_value_loop/results.json`.
- `scripts/run_power_delivery_benchmark.sh` passes and writes
  `benchmarks/power_delivery_proxy/results.json`.
- `scripts/run_design_review_benchmark.sh` passes and writes
  `benchmarks/design_review/results.json`.
- `kb_index.json` is generated.
- Non-claim lint passes.
- Next.js site builds.
- `scripts/visual_smoke_test.sh` passes for local route and screenshot proof.
- SwiftUI `RustRunner` points at a bundled CLI resource with an environment
  variable fallback for local development.
- The local macOS bundle opens a visible `Chip Heat Lab` window for recording.
- Native app runs do not leave stuck `chip_heat_cli` child processes after the
  Rust JSON exchange completes.
- `scripts/run_site_demo.sh` returns HTTP 200 for `/`, `/replay`, and
  `/knowledge` in the local review environment.
- The production Vercel deployment returns HTTP 200 for
  <https://chip-heat-lab.vercel.app> and
  <https://chip-heat-lab.vercel.app/replay> and
  <https://chip-heat-lab.vercel.app/knowledge>.
- `scripts/package_macos_release.sh hackathon-preview` creates an unsigned
  macOS zip, checksum, and manifest under `dist/`.

## Design-Review Ship Criteria

The locked demo is not ready merely because the heatmap renders. The design
review must be explainable end to end:

- baseline clustered SRAM fails the simplified review constraints;
- ranked candidates show at least one partial fix that still fails;
- the recommended intervention passes the simplified constraints;
- the recommendation is backed by `benchmarks/design_review/results.json`;
- the KB includes a `demo-explanations/design-review` entry;
- the site/native demo copy says "simplified" and does not imply validation.
